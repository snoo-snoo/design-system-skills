## Source summary

Ten heuristics: visibility of status; real-world match; user control; consistency; error prevention; recognition over recall; flexibility; aesthetic minimalism; error recovery; help/docs.

## Why it matters

- Shared critique language across products and skills
- Strong for UX Patterns and Feedback States (Wave A/B)
- Not a component spec — use to frame Principles, then ground with systems/standards

## Priority analysis targets (Phase 2)

1. Heuristics → taxonomy mapping (esp. #1, #5, #9 → Feedback States)
2. Where heuristics conflict with brand-heavy UI (document PriorityFloor)
3. Pairing with WCAG (e.g. status visibility vs live regions)

## Evidence class default

`Heuristic` (HIGH when aligned with standards/systems; alone = CANDIDATE max for component specifics)

## Risks / caveats

- Easy to over-apply “aesthetic and minimalist” as anti-enterprise-density dogma
- Heuristics are not testable success criteria like WCAG
