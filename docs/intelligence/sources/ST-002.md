## Source summary

Implementation-oriented companion to ARIA. Design patterns and functional examples for accessible components (tabs, dialogs, menus, etc.), plus fundamentals for landmarks, naming, and keyboard interfaces.

## Why it matters

- Bridges abstract WCAG criteria to **component interaction rules**
- Strong source for keyboard behavior and focus management conventions
- Ideal cross-check against Carbon/Polaris/Primer component a11y docs

## Priority analysis targets (Phase 2)

1. Dialog / Modal pattern (focus trap, escape, return focus)
2. Tabs, Disclosure, Combobox keyboard models
3. Accessible name/description requirements
4. Landmark usage guidance

## Evidence class default

`Standard-adjacent Pattern Spec` (authoritative practice; pair with WCAG for CORE)

## Risks / caveats

- Multiple valid implementation variants may exist per pattern — record variants, don’t force one code recipe into a visual rule
- Prefer native HTML semantics over ARIA when APG says so
