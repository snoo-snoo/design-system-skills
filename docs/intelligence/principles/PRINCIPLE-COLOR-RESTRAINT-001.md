# PRINCIPLE-COLOR-RESTRAINT-001 — Restrained Non-Semantic Color

```text
Principle:
Limit decorative color; reserve strong color for semantic roles
(action, status, emphasis, brand accents with intent).

Problem:
Excess unrelated color increases noise and weakens hierarchy/consistency.

Recommendation:
Default UI surfaces/text/icons to neutrals via semantic tokens. Add color
only when it communicates meaning or a deliberate brand moment.

Why:
Improves scanability and consistency; aligns with tokenized theming.

Context:
Product UI (SaaS, admin, consumer apps). Marketing landing pages may differ.

Exceptions:
Data visualization; brand-heavy campaigns; accessibility high-contrast modes
(still semantic). Stakeholder “make it pop” requests must pass P0–P2 first.

Evidence:
- VID-SAMPLE-002
- DS-002 Carbon Color (“additional colors used sparingly”)
- PRINCIPLE-COLOR-001

Confidence:
Medium–High

Category:
01 Foundations / Color

StatementClass:
Practice + System Convention

Maturity:
CORE (formalized as RULE-COLOR-RESTRAINT-001, Wave B 2026-08-20)

PriorityFloor:
P5 craft / P4 system consistency; never override contrast (P0)
```
